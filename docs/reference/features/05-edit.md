## EDIT — Timeline Arranger

The EDIT tab is theDAW's multi-track timeline. It arranges audio and MIDI clips, mixes them live, records parameter automation, and exports a mixdown — all in the browser, with only three features reaching the bundled local backend.

Core files: `frontend/src/components/audio/WaveformEditor.tsx` (view), `frontend/src/state/editorStore.ts` (document store), `frontend/src/state/liveMixer.ts` (playback engine), `frontend/src/state/effectChainStore.ts` + `frontend/src/lib/rackEffects.ts` (effects). The view is code-split and lazy-loaded (`DAWCenterPanel.tsx:82`).

### Arrangement
- **Tracks & clips** — add/remove tracks; drag clips horizontally (grid-snapped) or vertically between tracks; resize either edge (left edge also trims the source offset); split, duplicate (Ctrl/Cmd+D), and delete. Multi-select supports shift-range and ctrl-toggle. Zoom 5–400 px/sec via Ctrl+wheel. (`editorStore.ts:399`, `editorStore.ts:534`, `WaveformEditor.tsx:2043`)
- **Snap / BPM / loop / markers** — snap off · 1/4 · 1/8 · 1/16 against project BPM; a loop region cycles the transport; named markers seek on click (Phase F). (`editorStore.ts:860`, `liveMixer.ts:649`)
- **Song time on a clip** — audio from a library song, and every stem separated from it, carries `songTime` (`lib/clipSongTime.ts`): the song's library entry, its analysed tempo, and where the clip's audio sits in the song's own seconds. Every way audio enters EDIT writes it (a library drag or send, a stem row's drag, send or pick, "All stems", Separate Stems, DETAILS and the Library's "add to EDIT"), and `.tasmo` saves it as `song_time`. **SYNC** and **Time / Pitch** read the song's tempo and beats through it, so a stem SYNCs like the song it came from and a clip stretched twice still knows its beats. Audio that is no longer the song's (a reverse, a bounce, a new generation) drops it.
- **Use song tempo** — a library clip's context menu (**Use song tempo…**) and a library entry's menu (**Song tempo in EDIT**) open a preview of what the song's rhythm analysis makes the arrangement: the tempo before and after, the timeline second of the first downbeat and the bar it becomes, the number of tempo changes, the meters. Applying it writes the tempo map (one tempo per run of bars where the analysis has downbeats, a single tempo otherwise) and the meter map from the analysis's meter map, with bar 1 of the analysis on the clip's first downbeat; the EDIT bar the downbeat falls inside is cut to end on it. Everything before the clip keeps its tempo and meter. One undo takes both maps back. A song with no analysis offers to analyse it first (`lib/songTempo.ts`, `lib/songTimeLink.ts`, `components/audio/SongTempoDialog.tsx`).
- **Undo/redo** — 100-step history, 300 ms burst-coalescing, snapshots share arrays (no blob cloning). (`editorStore.ts:319`)

### Waveform editor
Each clip renders a frequency-coloured waveform of its trim window on an HTML `<canvas>` (`DJSemanticWaveform`), decoded once via Web Audio and cached as a 240-bin peak array on the clip (`WaveformEditor.tsx:150`, `editorStore.ts:901`). The moving playhead is driven imperatively via refs to avoid re-rendering the clip tree at 60 fps (`WaveformEditor.tsx:449`).

### Live playback (liveMixer)
Play schedules every clip as a Web Audio graph — `BufferSource → clipGain (fade) → trackGain → muteGain → insert FX → panner → session master bus → master FX rack → engine master` — so **volume/pan/mute/solo and per-clip mute are audible mid-playback** (`liveMixer.ts:275`, `liveMixer.ts:179`). MIDI (piano-roll) clips play live through a SoundFont/GM synth, one channel per track, 16-channel cap, via **spessasynth_core ^4.3.10 / spessasynth_lib ^4.3.7** (`liveMixer.ts:564`).

### Automation (Phase E)
Lanes record breakpoints for track volume, track pan, per-track FX, bus FX and master FX. WRITE/arm mode records timestamped points during playback; native vol/pan get sample-accurate `AudioParam` envelopes, FX params ride a ~40 Hz lookahead writer, and everything bakes into the offline render via `AudioParam` ramps + `suspend/resume` stepping (`editorStore.ts`, `liveMixer.ts`, `WaveformEditor.tsx`).

A lane can ride a **VST3 plugin's own parameter** on a track, a bus or the master. The automation panel's **Plugin parameter** picker lists every VST3 insert in the project, then the parameters the plugin's live host reports for it (a dot and one word beside the picker says whether the list is ready). The lane's key is the parameter's place in the plugin's list (`p<index>`), so it is drawn, recorded, played live, saved in `.tasmo` and reloaded like a rack lane. Offline, a freeze, the frozen-master preview and every export send each printed plugin the lanes on its parameters as `[frame, value]` curves (`lib/render/vstParamAutomation.ts`), and the backend moves the parameters at the start of every 256-frame block while it renders (`backend/modules/vst/param_automation.py`, `thedaw-vst-host --automation-json`). A bus's lanes are drawn on a strip of their own under the master's while automation is being edited.

**Volume line.** Each track row draws its `trackVolume` lane as a line over the lane (`components/audio/TrackVolumeLine.tsx`, rules in `lib/volumeLine.ts`, operations in `state/volumeKeyframes.ts`). A bare line is the fader. A right-click or a double-click adds a keyframe. Keyframes drag in time and level, the stretch between two drags as one, and a selected keyframe takes the arrow keys (0.1 dB, Shift 1 dB), a typed dB value and Delete. A volume or pan lane edited during playback is written onto its `AudioParam` again within 30 ms (`nativeLaneRearmPlan` in `liveMixer.ts`). Timeline preferences > Show volume line hides the lines.

### Effects, VST3 & .gan — one chain, one window per entry
Per-track, per-bus and master insert racks of client-side Web Audio effects (crossfeed, phantom bass, **Kargyraa Sub**, stereo widener, aural exciter, The Owl 3D spatializer, loudness contour, OWL-Pad, gater, bitcrush, ring mod, chop, parametric EQ, compressor, reverb, delay, hi/lo-pass, Ares) reconcile live and bake identically into the bounce (`rackEffects.ts`, `liveMixer.ts:253`). VST3 inserts play live through theDAW's live VST host (`lib/vstLive/vstLiveNode.ts`). An entry that names no plugin file, or whose plugin cannot open, passes its audio through.

An offline render cannot host a plugin, so a bounce that includes the racks prints each enabled VST3 insert on the local backend, one `/api/vst/process-file` call per plugin, at the insert's place in the chain (`lib/render/insertPrint.ts`). MIXDOWN, the Export dialog's Mix and Stems, a track freeze and the master freeze all print this way. Tracks and buses print upstream first, so a bus prints what its tracks' plugins made. The master VST chain runs last, over the finished mix, after the master rack. Each call sends the entry's captured state, the host that captured it and the plugin's name inside the `.vst3` file. A state the live host captured prints through theDAW's own render host, and any other state prints through pedalboard (`backend/modules/vst/router.py:856`). Before a bounce reads the document, each live plugin whose window is open or whose state changed is asked for its current state, so the print runs the settings dialed in live. Every call carries 32-bit float audio, and the finished file is encoded once. An export is written in the format the Export dialog chose.

A track with no clip in the rendered range prints no plugin, and in a mix neither does a muted track, a track soloed out or a muted bus. Send to Init and the Export dialog's Selection print the inserts the same way. The LOG reads "Printing <plugin> on <track, bus or Master>…" for each call and lists anything the plugin did not take. A plugin that cannot print stops the bounce, and the error names the plugin and where it sits. A bounce that prints a VST3 insert reports each render and each plugin call as progress on the render pill, and its cancel key stops it between calls. A track freeze keeps the tail a plugin rings out past the track's last clip. In Frozen mode the master panel's re-render key reads Re-render (stale) after a change to a clip, a track's mix or chain, a bus, the routing, the master chains, the tempo or an automation lane that is switched on and holds a breakpoint. Renaming a track or a bus, opening an empty lane and editing a lane that is switched off leave the key reading Up to date.

Built-in effects, VST3 plugins and `.gan` web plugins are **one concept** in the UI (`EffectWindows.tsx`). One **FX** button per track header and one master **FX** button open a compact chain list where FX/VST/GAN rows are identical; clicking a row opens that entry's own draggable floating control window, keyed by entry id so reopening focuses the existing window rather than duplicating it. Each window hosts exactly what MIX renders for that kind — `VstEmbedHost` for a plugin's native UI, `GanPluginStage` for a `.gan` surface, or the shared param tiles for a built-in. The former bespoke centered VST popup, the separate Ares popup, the `aresPanel` state and the paired MASTER FX / VST toolbar buttons are gone; Ares bridge ownership moved into the window host, and Live/Frozen moved into the unified master panel.

A **bus** takes the same inserts a track does. Its **FX** key on the mixer drawer's bus strip (below the EDIT timeline) opens the same chain list: built-in effects, VST3 plugins from the scan, `.gan` surfaces. A VST3 on a bus is hosted live on the bus strip, opens its own editor from its row, and can be bypassed, reordered and removed there; its captured state saves with the project, and a freeze and every export print it at its place in the bus chain. A master VST3 has a bypass dot of its own on its row, honored live and in every print.

Chain param pushes are **sticky**: `buildEffectChain` retains each live instance's full param state and `updateParams` merges into it, so a single-key push (one automation lane, one Perform pad punch, one XY axis) no longer resets that device's other params to catalog defaults.

### Autosave & crash recovery
The arrangement is autosaved to a content-addressed **OPFS** asset layer, so a refresh or crash no longer destroys in-memory clip audio (`lib/editorAutosave.ts`, `components/layout/AutosaveRecoveryNotice.tsx`). Clip blobs are written once per unique payload as `assets/<sha256>.bin` — split and duplicated clips share a single asset — alongside a debounced manifest of tracks, clips, FX, automation, markers, BPM and loop. At startup a recovery notice offers to restore, and **saving stays paused until the offer is answered** so a fresh session cannot overwrite the recoverable snapshot. Restoring rebuilds blobs and peak arrays and lands on EDIT.

### Stem separation from a clip
A timeline clip's context menu carries **Separate Stems → Tracks…**, which runs the Demucs sidecar on that clip and explodes the result into the arrangement (`WaveformEditor.tsx`). The modal picks stem count, device and quality; the clip's blob is bridged into the entry-keyed stems API via `importEntry` (the entry id is written back to the clip so a re-run hits the cache); a progress banner with Abort tracks the run; and each returned stem lands as its own colour-coded track placed at the source clip's exact position and trim, with the source clip muted (reversible). See [14-stems-analysis-convert.md](14-stems-analysis-convert.md) for the separation backend.

### Export
- **Mixdown** — `commitEdit` bounces the arrangement through an `OfflineAudioContext` (fades, track vol/pan, track + master FX, automation, teleports), prints every VST3 insert on each track, each bus and the master VST chain at its place in the chain through `/api/vst/process-file`, encodes WAV, imports to library, and downloads (`lib/render/insertPrint.ts`).
- **Send to Init** — renders the selected clips as they play: each track's rack and VST3 inserts, the buses and sends the routing takes them through, the master rack, the master VST chain and the automation. Solo is ignored, so the file holds exactly the clips picked. The WAV goes to the MAKE tab as init audio. A plugin that cannot load stops the render with a notice naming the plugin and its track.
- **Export options** — the export dialog renders the mix, one stem per picked track (each file named after its track), or the picked clips, over the whole project, the timeline selection or a Custom range, to the library, a download or both. The mix and a range of it print every VST3 insert on the tracks, the buses and the master. A stem prints its own track's rack and inserts, and no bus or master. A clip selection prints as Send to Init does; a clip's right-click menu has **Export Selection…**, which opens this dialog on the selected clips. **Render range…** on a timeline range and a track's **Freeze** print the same inserts. Only a bus that a playing track reaches runs its plugins.
- **Time/Pitch** — per clip, via backend `/api/studio/process` `time_pitch` (FFmpeg rubberband, atempo fallback) (`backend/modules/effects/router.py:275`).
- **Inpaint** — mask a region, regenerate via the local `/api/generate-jobs` Stable Audio backend, poll `/api/jobs/{id}`, replace the clip (`WaveformEditor.tsx:985`).

### Offline / no-cloud
Arrangement, playback, built-in FX, automation, MIDI synthesis and the bounce itself run in the browser Web Audio API. VST3 inserts play live through theDAW's live VST host and print through the local FastAPI backend. Time/pitch, inpaint and every VST3 print call only that local backend. No feature contacts any third-party cloud API, and EDIT works offline whenever the bundled backend is running.
